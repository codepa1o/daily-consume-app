# 女性健康第一版实现与验证

更新日期：2026-10-04。实现版本：1.2.1+6，线上业务后端已同步部署 1.2.1，并通过真实公网 HTTPS 验证。客户端更新包的发布步骤见 `docs/github-release-guide.md`。

## 使用流程

在“我的 → 个人资料”选择女生并成功保存后，底部出现女性健康。新旧账号默认未设置；切换为男生或未设置仅隐藏入口，历史数据保留。

进入后记录最近一次经期、填写通常的周期和经期长度。设置中提供可留空的数字输入，28/5 仅为提示示例，不自动写成个人数据。积累至少 3 个完整的首日间隔后，使用最近最多 6 个周期的中位数。

记录经期时选择开始和最后已确认出血日，可选择本次是否结束。批量录入须确认区间每天出血；只录入首日不会自动补造后续日期。已录入日期可在月历单独移除或补回；首日/末日调整通过经期编辑完成。结束现有经期而未改日期时，保留非连续的原出血日期。

月历为周一至周日，支持前后月、年月选择和回到今天。实际经期用深玫红，预计经期用浅粉和虚线，预计易孕窗口用浅紫，估计排卵日用紫色圆环。日期详情写明实际/预测，并提供每日记录编辑。点滴出血与症状不会建立新周期。

日历法暂按预计下次首日前 14 天估计排卵，前 5 天至当天为 6 天的估计易孕窗口。这是简化模型，不是测得的排卵或避孕依据。页面展示下一个周期；远期月份可浏览，但不会自动假设未记录的经期发生，过期预测不会滚动为下一周期或着色成实际记录。孕期、哺乳期、用药等情况可手动暂停预测。

## 数据与接口

数据库变更现由 Alembic 在部署时执行，API 启动不再执行建表 SQL。当前基线包含账号性别、周期设置、经期表及每日记录表；已有 1.2.1 数据库结构核对一致后登记迁移版本，保留全部业务记录。后续改表新增迁移文件，说明见 [数据库迁移指南](../database-migrations.md)。新客户端读取旧接口缺少的 gender 字段时仍按未设置处理，但编辑资料需要部署新后端。

| 路径 | 方法 | 行为 |
|---|---|---|
| me | GET / PUT | 返回或保存昵称、性别；性别为 unset/male/female |
| female-health | GET | 一次返回周期设置、经期及每日记录 |
| female-health/settings | PUT | 保存 cycle_length、period_length、paused；长度可为 null |
| female-health/periods | PUT | 新增或按 id 编辑 start_date、end_date、bleeding_dates |
| female-health/periods | DELETE | 按 id 删除当前账号的经期 |
| female-health/days | PUT / DELETE | 保存或按日期删除经量、痛经、症状、心情、点滴出血和备注 |
| female-health | DELETE | 删除健康记录；reset_settings=true 同时重置设置 |

每个健康请求需要有效会话，并再次从数据库检查当前性别。变更和资料更新使用同一个账号行锁，避免并发录入重叠区间或性别变更后继续写入。开放经期视为尚未结束的区间，开始下一次之前需结束原记录。相同的新记录重试返回既有 id；跨账号编辑返回不存在，跨账号删除不能影响原记录。

实际健康日期为 2000-01-01 至上海当天；客户端使用 UTC 表达日期值进行日期差运算，避免本机时区和夏令时导致少一天。健康表中只保存实际事件，预测为客户端派生结果。输入错误响应不回显备注或完整请求。

## 本地验证

- `flutter analyze --no-pub`：通过，无问题。
- `flutter test --no-pub`：全部 16 项通过。覆盖预测、跨月/闰日/跨年、空数据、暂停预测、月历语义、导航性别变化、窄屏表单验证及失败保留内容；同时运行既有登录/注册和健身测试。
- 设置 `TEST_DATABASE_URL` 后执行 `python -m unittest discover -s server -p test_female_health.py -v`：10 项 HTTP + 真实 PostgreSQL 检查全部通过。测试使用随机独立 schema 并在完成后删除，不依赖模拟数据库。
- Android release 构建通过；本次发布使用 `scripts/build_release.ps1` 推进为 1.2.1+6，输出 `build/app/outputs/flutter-apk/app-release.apk`，版本与内置更新日志同步。

测试数据库使用本机单独初始化的 PostgreSQL 18 实例，不启动或修改已有数据库服务。原版本验证覆盖旧表迁移；当前测试通过 Alembic 准备数据库，覆盖重复升级保留账号、资料校验、账号隔离、登录过期、并发重叠、重复请求、每日记录与经期分离、暂停设置、清空和重置。迁移接管及失败回滚检查见 `server/test_migrations.py`。

页面预览为测试数据生成，见 `design/female-health-calendar.png` 和 `design/female-health-history.png`。联网后端验证已完成；实际设备界面与安装验收仍需在手机上进行。
