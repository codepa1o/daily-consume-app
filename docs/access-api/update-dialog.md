# 居中更新弹窗与手动检查

实现日期：2026-10-04。

“我的”增加“检查更新”，显示系统实际安装版本。点击打开居中弹窗，检查最新版；无新版时明确反馈，404、连接错误和无效清单显示检查失败，允许重试。

自动冷启动检查和手动操作共用 `UpdateController` 的一个任务。首次更新日志完全关闭后开始自动检查；发现新版时显示弹窗并自动下载。下载与当前版本日志使用同一套弹窗管理，不叠加多个更新窗口。

下载数字来自实际接收字节，按十进制 MB 显示一位小数，约每 200 ms 刷新变化，百分比与进度条同步。下载完成后进入校验阶段；100% 表示字节下载完成，校验成功后显示安装更新和稍后安装按钮。更新内容在弹窗内展开查看。

取消下载需要确认，取消检查不需确认。取消会关闭 HTTP 客户端并等待临时文件清理，迟到响应不会覆盖新状态。失败重试从头下载；完整且校验一致的 APK 缓存可复用。稍后安装保留缓存，下次手动检查先获取新清单，再确认缓存仍对应当前目标版本。

下载和校验过程中，遮罩与系统返回键不会意外关闭弹窗。安装许可由 Android 系统处理；从权限设置返回且本次更新弹窗仍打开时，确认授权后继续安装。系统安装取消或失败保留已校验 APK，允许重试安装。

网络连接、TLS、HTTP 状态、文件读写、完整性校验及系统安装的失败分别展示；只记录阶段和异常类型，不输出凭据或临时签名下载地址。现有 HTTPS 下载域名、跳转次数、清单大小、APK 大小和 SHA256 校验约束保留，系统仍核对 APK 包名、版本和签名。

## 验证

- `flutter analyze --no-pub`：通过，无问题。
- `flutter test --no-pub`：全部 28 项通过，包含既有账号、健身、女性健康检查和 12 项更新控制/界面检查。
- Android release 构建通过，正式更新包为 `build/app/outputs/flutter-apk/app-release.apk`，版本 1.2.2+7；APK 包名、版本、内置日志与固定签名检查通过。
- 更新检查覆盖：真实接收字节在不足 1% 时也刷新、并发检查共用任务、取消与清理、迟到响应、无效清单和 404、错误 SHA 和不完整下载、缓存复用、安装许可与原生失败、手动入口和居中布局、日志排队、权限返回、小屏与大字体。
- 渲染预览使用测试数据，见 `design/update-dialog-preview.png`。

测试的 HTTP 与 Android 通道使用可控输入，下载内容实际写入临时文件并计算 SHA256；自动更新镜像和真机安装未在本次测试中验证。当前 Android 模拟器离线。

本次发布的版本元数据已推进为 1.2.2+7，更新日志原稿为 `docs/release-notes/1.2.2.txt`。新界面在安装 1.2.2 后生效，后续“检查更新”使用该版本的居中弹窗。客户端更新界面与已上线的 1.2.1 业务 API 兼容。
