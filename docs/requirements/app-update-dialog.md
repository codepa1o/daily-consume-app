# 更新弹窗与手动检查更新需求

日期：2026-10-04。状态：已实现，版本推进为 1.2.2+7；静态分析及全部 28 项 Flutter 测试通过。设备安装验收需安装本次新包后进行。

## 1. 背景与目标

用户已确认：同一更新开启 VPN 后下载成功，支持此次失败与原网络到 GitHub 下载服务器的连接路径有关。

现有更新流程在 App 冷启动时检查，发现新版后自动下载，下载状态和操作按钮展示在底部面板；有进度条，但没有下载字节数显示。“我的”只有更新日志，没有手动检查更新入口。多个下载异常会被统一显示为网络失败。

本次明确需求：更新过程改为屏幕中间的弹窗；实时显示已下载多少 MB、总大小和进度条；“我的”新增“检查更新”，点击后检测新版。

以下的关闭策略、状态文案、刷新频率及失败分类为产品建议。

## 2. 入口与触发

- “我的”新增“检查更新”，建议放在“更新日志”上方，副标题显示实际安装的当前版本。
- 与性别无关，所有能进入“我的”的账号均显示该入口。
- 点击立即打开居中弹窗，显示“正在检查更新…”并发送一次新的更新请求。
- 没有新版：显示“当前已是最新版本”，展示当前版本并提供“确定”。
- 有新版：在同一弹窗中展示目标版本和更新信息，进入下载流程。
- 检查失败：显示具体检查失败信息，提供“重试”和“关闭”；不能将超时、404 或无有效清单显示成“已是最新版”。
- 保留现有冷启动自动检查和发现新版后自动下载的行为，展示形式改为居中弹窗。
- 冷启动检查失败保持现有不阻断业务的行为；手动检查失败则在弹窗中明确反馈。
- 自动检查和手动检查复用同一份更新任务。任务正在进行时再次点击，显示当前任务进度，不重新下载或产生第二个更新弹窗。

## 3. 弹窗布局

弹窗居中，背景有遮罩；宽度适配小屏手机，更新日志过长时仅内容区域滚动，底部操作按钮保持可用。

展示字段：

- 标题：检查更新 / 正在下载更新 / 下载完成 / 更新失败，随阶段变化。
- 当前安装版本、目标版本。
- 更新内容：可展开查看，仍在同一弹窗内，避免多层更新弹窗。
- 已下载大小 / 安装包总大小，例如“18.6 MB / 56.0 MB”。
- 线性进度条和百分比，例如“33%”。
- 当前阶段：连接中、下载中、校验中、等待安装等。
- 与阶段对应的操作按钮。

下载示例：

```text
正在下载更新 · 1.2.2
当前版本：1.2.1

已下载 18.6 MB / 共 56.0 MB
[██████░░░░░░░░░░░░] 33%

查看更新内容
取消下载
```

## 4. 下载数字与实时进度

- 以实际接收的字节数计算大小和百分比，不用定时器模拟进度，也不从已取整的百分比反推大小。
- UI 统一使用 MB，1 MB = 1,000,000 字节，保留 1 位小数；当前 1.2.1 安装包约为 56.0 MB。
- 总大小来自有效更新清单；百分比为实际已下载字节数 / 清单总大小。
- 建议每 200 ms 左右刷新一次，避免每个小数据块都重建界面；完成、失败和阶段切换立即刷新。
- 连接阶段显示“正在连接下载服务器”，进度为 0；下载阶段显示实际数字。
- 下载收到全部字节后显示 100%，随后明确显示“正在校验安装包”，使用不确定进度指示器。
- 100% 仅表示下载完成，不能显示为已经安装或更新成功。

## 5. 状态与操作

| 状态 | 展示 | 操作 |
|---|---|---|
| 检查中 | 加载指示器、当前版本 | 关闭，取消该次检查 |
| 已是最新版 | 当前版本、明确结果 | 确定 |
| 准备下载 | 目标版本、包大小、更新内容、连接状态 | 取消下载 |
| 下载中 | 实时 MB、百分比、进度条 | 取消下载 |
| 校验中 | 校验说明、不确定进度 | 暂时禁用关闭，避免误操作 |
| 等待安装许可 | 下载和校验已完成、授权说明 | 允许安装更新 / 稍后安装 |
| 可安装 | 下载完成、目标版本 | 安装更新 / 稍后安装 |
| 下载失败 | 具体原因及可行提示 | 重新下载 / 关闭 |
| 检查失败 | 无法获取更新信息及原因 | 重试检查 / 关闭 |
| 安装未完成 | 安装取消或失败的说明 | 重试安装 / 稍后安装 |

关闭规则建议：

- 下载和校验时，不因点击遮罩或系统返回键而意外关闭。
- 下载时点击“取消下载”需确认；确认后终止网络请求、清理未完成文件并关闭弹窗。
- 第一版取消或失败后的重试仍从头下载；断点续传不属于本次范围。
- 下载并校验完成后选择“稍后安装”，保留可复用的安装包；再次点击检查更新时可回到安装操作，仍确认缓存对应有效的目标版本。
- 更新日志与更新过程弹窗排队展示：先关闭当前版本的首次更新日志，再显示新版本更新弹窗，避免叠加。
- Android 系统的安装授权和安装确认仍由系统完成；从系统设置返回时继续显示正确阶段。

## 6. 失败提示

结合此次实际网络问题，明确区分：

- 检查/连接超时：无法连接 GitHub 更新服务器，可切换网络或检查代理设置后重试。
- 下载中断：下载连接已中断，请重新下载。
- 安装包校验失败：安装包校验未通过，请重新下载。
- 文件写入失败：无法保存安装包，请检查可用存储空间等。
- 安装失败：显示系统安装阶段的原因，不统一写成下载网络失败。

不将“必须开启 VPN”作为所有失败的固定提示。诊断记录只保留异常类型、阶段和必要状态码，不记录临时签名下载链接、凭据或业务数据。

## 7. 验收场景

1. “我的”可看到检查更新与当前版本；点击后出现居中弹窗。
2. 无新版、有新版、网络失败分别显示正确结果。
3. 下载数字与实际收到的字节同步增加，百分比和进度条一致。
4. 100% 后仍展示校验阶段，校验成功后才进入安装操作。
5. 底部旧更新面板移除，不同时展示两套更新过程 UI。
6. 连续点击、自动检查与手动检查重叠时只有一个任务和一个更新弹窗。
7. 更换网络或代理后可重试；真实失败原因不丢失。
8. 取消下载后任务终止；稍后安装可复用已校验缓存，不重新下载相同包。
9. 从安装授权设置返回、取消系统安装、App 切到后台再返回时，状态正确。
10. 小屏和较大字体下，文字可读、日志可滚动、按钮可点击；更新弹窗不叠在首次更新日志上。

本次先调整展示与手动入口；更新源继续使用 GitHub Release。国内下载源、下载镜像、断点续传和后台下载通知单独评估。
