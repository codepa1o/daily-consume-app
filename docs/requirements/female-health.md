# 女性健康功能需求梳理

需求整理日期：2026-10-03。状态：第一版已实现并验证，线上业务后端已于 2026-10-04 同步部署 1.2.1；提醒、导出和特殊阶段工具仍为后续功能。

## 1. 目标与现状

新增“女性健康”业务栏，以经期管理为第一版核心，完成个人资料设置、经期记录、月历查看、周期预测和历史回顾。

现有应用为 Android 优先的 Flutter 应用，底部为身体、饮食消费、健身、我的。业务数据由登录账号隔离并保存到服务器 PostgreSQL，使用业务功能需要联网。当前账号包含用户名、昵称、注册时间，尚无性别字段；“我的”需要补充可编辑的个人资料入口。

本文中入口条件、按月查看和不同颜色标注属于用户明确需求；预测算法、具体颜色、版本划分等属于产品建议。

## 2. 显示条件与个人资料

- 路径：我的 → 个人资料 → 性别，选项为“未设置 / 男生 / 女生”。
- 新账号、旧账号迁移后的默认值均为“未设置”；不根据昵称、头像或其他记录推断性别。
- 仅服务器成功保存为“女生”后展示女性健康栏；男生、未设置均隐藏。
- 建议导航顺序：身体 → 饮食消费 → 健身 → 女性健康 → 我的。“女性健康”为完整栏名，可在窄屏导航用“女性”，页面标题保留完整名称。
- 保存成功即刷新导航，无需重启；保存失败保留原资料和原导航。
- 若当前女性健康页因性别修改而被隐藏，跳转到“我的”；其余页面保持当前选中的业务，不因位置变动跳错页。
- 隐藏不删除记录；重新设为女生后恢复原记录与设置。删除健康数据须为独立操作并确认。
- 每个账号独立保存性别与健康数据；退出或切换账号立即清除上一账号在内存中的页面、记录和待执行提醒。
- 个人资料尚未加载成功时不展示该栏；失败提供重试。

## 3. 第一版功能

### 3.1 首次使用

首次进入引导填写：最近一次经期开始日期、通常周期天数、通常经期天数，可补充最近一次经期结束日期。

- 区分“周期长度”和“经期长度”，给出简短示例。
- 周期长度为两次经期首日之间的日期差；经期长度为实际记录的出血天数。
- 允许跳过设置并先查看空月历；缺少最近开始日期或周期长度时不显示预测。
- 若提供 28 天周期、5 天经期作为填写示例，必须标明为可修改的示例，未经用户确认不视为个人数据。
- 已结束的历史经期可按起止日期整段补录；只知道首日时只记录首日，不补造其余日期。

### 3.2 经期记录

- 快捷操作：“经期开始”“记录今天”“经期结束”“补录历史”。
- 点击月历任一天查看、新增或修改该日记录。
- 记录经期首日、实际出血日期及末次出血日；允许经期跨月、跨年。
- 当前经期可保持“进行中”，结束按钮明确填写的是“最后一天出血”，不是点击按钮当天。
- 未确认的后续日期不能自动成为实际经期；用户可一次确认过去连续几天均有出血。
- 可编辑起止日期、删除一次经期或修改一天的记录；修改后立即更新月历、统计与预测。
- 可选每日字段：经量（少 / 中 / 多）、痛经程度（无 / 轻 / 中 / 重）、症状（腹胀、头痛、腰酸、疲劳、乳房胀痛等）、心情及备注。
- 点滴出血单独记录，不自动算作新经期首日。
- 同一天只能有一份每日记录，重试或重复点击不新增重复数据。
- 实际记录日期不得晚于今天；未来日期仅用于预测。起止倒置和重复、重叠的经期段须提示修正。

### 3.3 月历与日期详情

默认显示当前月，支持上月、下月、年月选择和“回到今天”；周一至周日排列，跨月记录连续展示。

| 日期类型 | 建议视觉 | 日期详情文字 |
|---|---|---|
| 实际经期 | 深玫红实心背景 | 已记录经期、第 N 天 |
| 预测经期 | 浅粉背景及虚线边框 | 预计经期 |
| 预测易孕窗口 | 浅紫背景 | 预计易孕期 |
| 估计排卵日 | 较深紫色圆环或图标 | 估计排卵日 |
| 有症状或备注 | 日期下方小圆点 | 有记录 |
| 普通日期 | 默认背景 | 暂无记录 |

- 月历下方固定提供图例，不只依靠颜色区分；日期详情写明“已记录 / 预计 / 估计”。
- 今天和选中日期使用独立边框，不覆盖经期类型；颜色对比需保证日期可读。
- 实际经期优先于预测；排卵日作为易孕窗口中的特殊标识；症状圆点可叠加。
- 排卵日是一日的估计，易孕窗口是多日的预测范围，不能混为一种状态。
- 已过去但未确认发生的预测经期，不转为历史事实；过期预测可在详情保留参考，不当作已记录日期着色。
- 普通日期不标成“安全期”。

### 3.4 首页概览

顶部展示与当前资料相符的内容：

- 已确认经期进行中时：“经期记录进行中，今天为本周期第 N 天”。
- 未在经期且有可用预测时：“下次经期预计 MM/DD 开始，距预计日期 N 天”。
- 超过预计日期仍无新记录时：“已超过预计开始日 N 天，请确认是否需要补录”，不直接断言月经推迟或怀孕。
- 最新一次经期、典型周期长度、典型经期长度。
- 数据不足时显示“补充记录后可查看预测”；无法判断当前阶段时显示“状态待确认”。

## 4. 预测规则建议

以下为第一版的简化计算方案，需要在实现时固定规则；不是医学诊断或经过校准的概率模型。

1. 最近一次真实经期首日是预测锚点；不能从每个月固定日期推算。
2. 初期使用用户确认的通常周期和经期长度，显示“基于你填写的周期估计，历史记录较少”。
3. 有至少 3 个可用的完整周期间隔（需要至少 4 次首日记录）后，建议取最近最多 6 个周期长度的中位数；经期长度只使用已结束且记录完整的经期。
4. 不自动丢弃长短不一的真实周期；缺失、重复或重叠数据先提示核对，不把可疑间隔直接纳入计算。
5. 预计下次首日 = 最近实际首日 + 典型周期长度；预计经期末日 = 预计首日 + 典型经期长度 − 1。
6. 日历法排卵估计可暂按“预计下次首日前约 14 天”作为模型假设；易孕窗口可采用估计排卵日前 5 天至当天共 6 天。必须明确这只是简化估计，不能宣称测得排卵，也不能保证窗口外无受孕可能。
7. 已有记录变化较大、资料太少或预测已经过期时，降低展示确定性，提示“预测参考性有限 / 需要更新记录”；不生成伪造的准确率。
8. 默认重点展示下一周期，未来月份可展示推算结果并标明“远期估计”；真实新记录到来后重新锚定。错过预测日期后不自动假设经期已发生并继续滚动。
9. 新增、编辑、删除经期，以及修改周期设置时，重新计算所有受影响的预测与摘要。
10. 提供“暂停预测”设置；孕期、哺乳期、使用激素类药物等情况不沿用普通周期模型生成肯定结论。第一版可用暂停功能覆盖，后续再增加详细状态记录。

预测说明固定可查看：“经期、易孕期和排卵日为估计，仅供日常记录参考，不能作为避孕或诊断依据。”

## 5. 历史与统计

- 按时间展示每次经期的开始、结束、已记录出血天数及与上次首日的间隔。
- 展示最近 6～12 个月的周期长度和经期长度趋势。
- 未结束记录明确标注“进行中”；漏记导致的周期不标为确切完整周期。
- 无足够样本时不显示平均或典型周期，显示可用记录数量。
- 统计真实记录，预测数据不得纳入统计。

## 6. 后续功能建议

| 优先级 | 功能 | 范围 |
|---|---|---|
| P1 | 经期提醒 | 默认关闭，用户开启后选提前天数与时间；预测变化重新安排，隐藏该栏或退出账号取消 |
| P1 | 记录提醒 | 可提醒补录及确认经期结束；不能自动补记录 |
| P1 | 易孕期提醒 | 独立开关，与经期提醒分开 |
| P1 | 历史导出 | 用户主动导出 CSV 或 PDF，便于自己查看或就诊使用 |
| P2 | 更详细的生理记录 | 基础体温、排卵试纸、分泌物等，结合实际用途增加 |
| P2 | 特殊阶段 | 孕期、产后、哺乳期、围绝经期及用药因素；独立设计相应规则 |
| P2 | 健康知识 | 经来源审校的基础知识及就医信息 |

第一版建议交付：性别条件显示、首次设置、经期记录及少量可选症状、彩色月历、下次经期与易孕窗口估计、历史及基础统计、暂停预测、独立删除健康数据。

提醒与导出可放第二阶段；完整孕期工具、伴侣共享、诊断、复杂 AI 建议不属于本次第一版范围。

## 7. 数据与隐私要求

- 性别、周期设置、经期记录和每日记录随登录账号保存到服务器，遵循项目现有的联网及账号隔离规则。
- 预测由真实记录与设置派生，不能作为实际健康事件保存；保持各设备的计算规则一致。
- 健康接口由服务端会话确定数据归属，隐藏入口不能代替账号鉴权。
- 按日期保存健康记录，使用明确的日期语义，避免时区转换把记录挪到相邻日。
- 不将症状、备注和完整健康请求写入普通日志；首次记录前简要说明数据随账号保存在服务器及可删除方式。
- 提醒若后续启用，默认锁屏文案用“你有一条健康提醒”，用户可选择详细文案；默认不展示经期及易孕信息。
- 独立删除提供“仅删除记录 / 删除全部女性健康数据并重置设置”的明确选项与确认，不能因性别变化自动执行。
- 保存失败不显示为已成功记录，保留表单内容方便重试；切换账号后不能保留前一账号的表单。

## 8. 验收场景

1. 新账号、旧账号、男生账号均不显示女性健康；保存为女生后立即显示，重登后保持。
2. 女生切换为男生或未设置后立即隐藏；再次改为女生后原数据恢复；当前页与底部导航保持一致。
3. 从账号 A 切换到 B，不展示 A 的性别、健康记录、输入草稿或提醒。
4. 9 月 29 日至 10 月 3 日的经期在两个月历中正确显示；跨年、闰年二月同样正确。
5. 录入实际经期后覆盖重叠预测；预测、实际经期和排卵估计始终可区分。
6. 首次未填写信息时月历为空，不产生默认预测；仅记录首日不自动补成 5 天实际经期。
7. 修改、补录或删除历史记录后，月历、趋势、摘要和下一周期预测同步更新。
8. 结束日期早于开始日期、未来实际记录、重复或重叠经期均有明确提示；症状可独立于经期保存。
9. 超过预测日期且无新记录时，提示确认或补录，不把预测视为已发生，也不推断怀孕。
10. 暂停预测后保留真实记录和历史，停止生成预测；恢复后根据最新可用数据重新计算。
11. 网络失败不伪报保存成功；旧版账号资料升级后不被默认为女生。

## 9. 调研依据

- [Apple：周期跟踪使用说明](https://support.apple.com/en-ie/120356)。参考经期与症状记录、实际和预测的视觉区分、周期历史、预测和提醒独立设置，以及预测不能用于避孕或诊断的说明。
- [NHS：月经周期与生育](https://www.nhs.uk/conditions/periods/fertility-in-the-menstrual-cycle/)。参考周期起点定义，以及排卵时间存在差异、不能固定假设每个人都在周期第 14 天排卵的说明。
