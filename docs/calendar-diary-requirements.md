# 身体页「生活日历」需求建议

状态：首版已在本地实现并验证，尚未部署线上或发布。结果见[接口与验证记录](access-api/journal.md)。
调研日期：2026-10-04。

相关文件：[实现前规划](calendar-diary-implementation-plan.md)、[后续功能 TODO](calendar-diary-TODO.md)。

## 1. 目标与项目背景

在「身体」页底部增加生活日历，支持按日期记录日记、保存备忘和管理简单待办，方便记录与回顾生活。

现有身体页依次展示身高/体重、体重趋势、记录体重和更新身高按钮。新增模块放在这些内容之后，不新增底部导航项。项目为 Android 优先的 Flutter 应用，业务数据按账号保存在服务器 PostgreSQL，需要登录并联网使用。健身和女性健康已有各自的月历。

生活日历面向通用生活记录，不强制填写身体信息；既能写训练感受，也能记工作、学习和日常琐事。

## 3. 建议首版范围

### 3.1 月历

- 模块名称为「生活日历」，嵌入身体页底部，默认显示本月并选中今天。
- 周一作为每周第一天，与现有健身统计口径保持一致。
- 支持上一月、下一月、年月跳转和「回到今天」。
- 今天与选中日期分别标识；有记录的日期显示标记，并提供图例。
- 日记、普通备忘和未完成待办用小图标或标记区分，不只依靠颜色。
- 点日期后，月历下方展示当天记录；空日期展示「这一天还没有记录」及新增入口。
- 月历仅展示记录标记，正文在下方列表中展示，避免日期格内堆积文字。

### 3.2 日记

- 选定日期后点击「写日记」，进入完整编辑页面，便于输入长文。
- 字段：归属日期、可选标题、必填正文；首版支持纯文本、换行和表情。
- 同一天允许多篇日记，分别编辑和删除。
- 可以补写历史日记；建议未来日期仅允许新增备忘，不允许写日记。
- 日记归属日期和实际创建时间分开保存，补写后出现在正确的日期。
- 标题为空时，列表使用正文首行作为摘要，不强制填写标题。

### 3.3 备忘与简单待办

- 点击「记备忘」，填写日期、标题和内容；标题或内容至少一项非空。
- 普通备忘可记录想法、购物清单、训练安排等，不要求完成状态。
- 编辑时可开启「作为待办」，展示完成勾选框，支持完成与取消完成。
- 支持过去、今天和未来的日期；可以改日期，改后移动到新日期。
- 待办的日期表示计划完成日，完成后仍保留在原计划日期下，不自动移动。
- 当天列表优先展示未完成待办，其次日记/普通备忘，已完成待办可折叠。
- 逾期事项保留在原日期，显示「已逾期」；不自动顺延或创建重复记录。
- 首版不含系统定时通知，界面不得将「设置日期」描述为「到时提醒」。

### 3.4 浏览、搜索与编辑保护

- 记录列表展示类型、标题/摘要和待办状态；点击进入详情与编辑。
- 提供「全部记录」入口和跨日期关键词搜索，搜索标题与正文，可按日记/备忘筛选。
- 搜索结果展示归属日期，点击可查看详情并定位到该日期。
- 保存时显示进度，防止重复点击产生重复记录；成功后更新当天列表和月历标记。
- 保存失败保留编辑内容，允许重试；有未保存修改时退出提示「保存 / 放弃 / 继续编辑」。
- 空白内容不能提交；删除前确认，并同步更新列表和月历。
- 月历模块独立展示加载、空白及失败状态，失败后可重试，不阻塞身体页其他功能。

## 4. 页面结构与操作流程

身体页现有内容 → 生活日历标题与「全部记录」 → 月份导航和月历 → 所选日期 → 「写日记 / 记备忘」 → 当天记录列表。

典型操作：

1. 补写昨天：切换到昨天 → 写日记 → 输入内容 → 保存 → 昨天出现日记标记。
2. 安排明天：选中明天 → 记备忘 → 输入「买训练用的弹力带」 → 开启作为待办 → 保存。
3. 完成事项：点击待办勾选框 → 进入已完成区域；再次点击可恢复。
4. 查找旧记录：全部记录 → 输入「跑步」 → 查看匹配的日记/备忘及日期。

## 5. 推荐后续功能

| 优先级 | 功能 | 价值及范围 |
| --- | --- | --- |
| 优先扩展 | 当日生活概览 | 只读展示该日已有体重、餐费、训练记录及跳转入口；无记录显示「未记录」，不推断为 0 或未训练 |
| 优先扩展 | 可选心情、标签和简短模板 | 日记可选心情；按「训练感受、身体状态、今日小结」快速起笔，模板不覆盖已有正文 |
| 优先扩展 | 单次定时提醒 | 给待办设置明确时间；增加 Android 通知权限、修改/取消提醒和重启后的恢复处理；通知默认不展示私密正文 |
| 后续 | 重复待办 | 支持每日/每周；每次发生独立完成，编辑时区分本次和整个系列 |
| 后续 | 图片、导出、日记锁 | 图片需配套上传和删除；支持文本导出；日记锁属于额外访问保护，不等同于端到端加密 |
| 后续 | 持久草稿、周/月回顾 | 草稿按账号隔离；回顾先展示记录天数、已完成事项与用户填写的心情分布 |

女性健康已有独立的心情、症状和备注记录，通用日记不自动写入或覆盖这些字段；若后续展示健康摘要，应由用户选择开启。

首版暂缓周/日时间轴、拖拽排期、外部日历同步、协作共享、AI 自动写日记及自动健康结论。

## 6. 数据与实现约束

- 延续服务器保存、按账号隔离的模式；退出登录或切换账号时清空内存中的记录和未保存编辑内容。
- 记录建议包含：ID、所属账号、类型（日记/备忘）、归属日期、标题、正文、是否待办、完成状态、创建和修改时间。首版无需为普通笔记创建第三种实体。
- 归属日期按日历日期存储，不因时区换算发生偏移；创建/修改时间单独存储。
- 月历按可见月份查询记录数量及状态摘要，日期列表查询当天内容；全部记录和搜索分页加载。
- 日记和备忘独立于身高/体重、饮食、健身及女性健康数据，删除日记不连带删除其他记录。
- 日期范围建议从 2000-01-01 开始，未来备忘支持到当前年份后 10 年；标题建议最多 100 字、正文最多 20,000 字，客户端与服务器统一校验。
- 多设备同时编辑需检测修改冲突，冲突时保留当前输入，提示重新加载后处理，避免静默覆盖。
- 需要新增客户端页面、后端接口及数据库迁移，客户端和后端应配套发布。现有服务器存储不应被描述为端到端加密。

## 7. 首版验收标准

1. 身体页底部可看到月历，跨月、跨年和闰年日期正确；今天与选中日期区分清楚。
2. 同一天可新增多篇日记和备忘，补写历史内容后落在所选日期，未来日期只能记备忘。
3. 编辑、改日期、完成/取消完成、删除后，列表和月历标记同步更新。
4. 普通备忘没有完成框，待办可以勾选；已完成与逾期状态可辨认。
5. 搜索覆盖所有日期，而不仅是当前月；无结果有清晰提示。
6. 关闭并重新打开 App、卸载后重新登录，同账号已保存记录仍可读取；不同账号不能访问彼此记录。
7. 网络失败不会丢失当前页面的输入，不会误报保存成功；月历失败不影响身高/体重操作。
8. 编辑中退出有明确处理选项，空白提交被拦截，重复点击保存不会新增重复记录。
9. 未来计划日期不触发首版尚未提供的通知；既有健身和女性健康功能正常。
