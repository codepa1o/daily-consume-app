# 阿里云公网连接操作

目标实例：华东 1（杭州，`cn-hangzhou`），`i-bp10wel7neiak77wz4mb`，公网 IP `47.99.142.117`。

主机上的 Nginx、HTTPS 443 和 PostgreSQL/后端已经部署，UFW 已允许 443。当前问题是外部 TCP 443 连接超时，外部请求未到达主机；22、80 可访问。独立澳大利亚节点也验证了 80 可连接、443 超时。

## 1. 检查实际绑定的安全组

打开 [ECS 控制台](https://ecs.console.aliyun.com/)，选择杭州地域，在实例列表查找上述实例 ID。进入实例详情，再打开“安全组”页签，点击该实例实际绑定的安全组 ID。

选择“入方向”，点击“手动添加/增加规则”，设置：

| 字段 | 值 |
|---|---|
| 授权策略 | 允许 |
| 协议 | HTTPS（443）或自定义 TCP |
| 目的端口范围 | 443/443（若界面是单端口，填 443） |
| 来源/授权对象 | IPv4 地址段 0.0.0.0/0 |
| 优先级 | 建议 1；检查同优先级拒绝规则 |
| 描述 | 日常 App HTTPS API |

保存后检查规则已生效且该安全组仍关联本实例。入方向对应用户访问服务器；宝塔防火墙、主机 UFW 与 ECS 安全组是不同控制层。

若界面有可选的“目的 IP”，保留默认全部地址；如果必须指定，填写实例私网 IP（本实例为 `172.24.105.64`），不要填公网 IP。此项容易导致看起来有 443 允许规则，但实际流量不匹配。

## 2. 已有 443 允许规则时

- 确认修改的是上述实例实际绑定的安全组，地域为杭州，规则方向为“入方向”。
- 来源应是 IPv4 `0.0.0.0/0`，而非只有 IPv6 `::/0`、某个固定 IP 或某个安全组。
- 检查所有绑定安全组里是否有匹配 443 的拒绝规则，包括“全部协议/全部 TCP”的拒绝规则。
- 数字越小优先级越高；同优先级的拒绝优先于允许。若有同优先级拒绝覆盖 443，应调整对应拒绝规则的范围或优先级，使 443 的允许规则实际匹配。
- 如果启用了阿里云云防火墙，继续检查公网入方向访问控制是否阻止 `47.99.142.117:443`。
- 如果交换机绑定了网络 ACL，也检查该 ACL 的入站 443 与响应流量规则。默认未配置这些产品时无需新建它们。

本次公网只需开放 HTTPS 443。后端 8091 和 PostgreSQL 5432 保持仅供本机访问。

## 3. 从电脑验证

在 PowerShell 执行：

```powershell
Test-NetConnection 47.99.142.117 -Port 443
```

应看到 `TcpTestSucceeded : True`。再在此项目根目录执行：

```powershell
curl.exe --noproxy "*" --connect-timeout 10 --cacert assets/server_ca.pem https://47.99.142.117/api/v1/health
```

应返回 `{"status":"ok"}`。这是带证书验证的 HTTPS 检查；项目 APK 已内置该服务器证书，不需要给手机另行安装证书。

如果 TCP 443 成功但 HTTPS 失败，把错误信息交给维护者检查；如果 TCP 443 仍失败，提供实际绑定的安全组 ID 与完整 443 规则（方向、协议、端口、来源、目的 IP、优先级、允许/拒绝），以便继续定位。

## 4. 安装与导入

覆盖安装 GitHub Release 的新版 APK，保留旧本机记录。注册或登录后，确认记录属于当前用户名，再执行导入。导入完整并经服务器核对后，App 才清理旧 SQLite；不要在导入前卸载旧版。

官方依据：[使用安全组](https://help.aliyun.com/zh/ecs/user-guide/start-using-security-groups)、[安全组规则与优先级](https://help.aliyun.com/zh/ecs/user-guide/security-group-rules)。
