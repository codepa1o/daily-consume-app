## 1. 首版目标和范围

在「身体」页底部嵌入生活日历，交付完整的「选日期 → 查看记录 → 写日记/记备忘 → 编辑、删除、完成待办 → 搜索回顾」流程。

| 首版包含 | 放入后续 TODO |
| --- | --- |
| 月历、月份/年月切换、回到今天、记录标记 | 当日体重/餐费/训练概览 |
| 一天多篇纯文本日记、历史补写 | 心情、标签、日记模板 |
| 普通备忘、简单待办、完成/取消、改日期 | 定时提醒、重复待办 |
| 当天列表、全部记录、跨日期搜索、类型筛选 | 图片、导出、日记锁 |
| 账号隔离、编辑保护、修改冲突检测 | 持久草稿、周/月回顾 |

当前采用需求草案的默认规则：周一为一周起点；未来日期只允许记备忘；日记正文必填、标题可选；备忘标题或正文至少一项非空。待办完成后保留在计划日期，逾期不自动顺延。首版的日期不含通知含义。

首版不引入新的底部导航项、离线业务数据库或状态管理框架。月历使用 Flutter 现有布局能力；后端延续 FastAPI、psycopg 和手写 SQL，数据库变更通过 Alembic 增量迁移。

## 3. 数据设计

使用一张 `journal_entries` 表保存日记和备忘；简单待办属于备忘的状态。

| 字段 | 作用 |
| --- | --- |
| `id` | 服务器生成的记录主键 |
| `user_id` | 从会话确定的所属账号，关联用户表 |
| `entry_date` | PostgreSQL DATE，记录归属日期 |
| `kind` | `diary` 或 `memo` |
| `title`、`content` | 标题与纯文本正文 |
| `is_todo`、`completed` | 是否待办、是否完成 |
| `version` | 从 1 开始的整数修改版本，成功修改递增 |
| `client_request_id` | 单次创建操作的随机标识，用于网络失败后安全重试 |
| `created_at`、`updated_at` | 带时区时间戳 |

数据库约束：`kind` 值合法；日记不能设为待办或已完成；普通备忘不能为已完成；日记正文去除空白后非空；备忘标题/正文不能同时为空；标题最多 100 个字符、正文最多 20,000 个字符；`version` 为正数。

索引：按 `(user_id, entry_date, created_at, id)` 支持月份与日期查询；按 `(user_id, client_request_id)` 唯一，防止创建重试产生重复记录。同一账号同一天不设唯一约束，允许多条内容。

日期规则：归属日期始终使用 `YYYY-MM-DD`，不把午夜时间戳转成 UTC 再决定归属日；「今天」和未来日记校验统一使用 Asia/Shanghai。支持从 2000-01-01 到当前年份后 10 年的日期；跨年后刷新范围。创建/修改时间以 UTC 存储，显示时按界面时区转换。

删除日记只删除对应记录。迁移为新增表，不修改现有业务表与数据；新增字段只覆盖本期需要的行为，不预建图片、提醒或标签表。

## 4. 接口契约建议

以下是拟新增接口，相对于现有 `api/v1/`，实施前固定输入输出契约。

| 方法 / 路径 | 用途及主要输入 |
| --- | --- |
| `GET journal/calendar` | `month=YYYY-MM`；返回每日的日记数、普通备忘数、未完成及已完成待办数 |
| `GET journal/entries` | 可选 `date`、`kind`、`q`；`limit`、`offset` 分页；返回摘要项、总数和下一页状态 |
| `GET journal/entries/{id}` | 返回一条完整记录，包含正文和 version |
| `POST journal/entries` | `client_request_id`、日期、类型、标题、正文、待办和完成状态；返回服务器记录 |
| `PUT journal/entries/{id}` | 完整可编辑字段及 `expected_version`；用于改内容、日期及完成状态 |
| `DELETE journal/entries/{id}` | `expected_version`；只删除当前版本的当前账号记录 |

列表只返回正文摘要而非整篇正文；编辑时读取详情。当日列表同样分页，避免单日记录过多。建议默认每页 50 条、最大 100 条；全部记录按归属日期降序、创建时间降序、ID 降序排列，保证相同日期顺序确定。

指定 `date` 查询时，服务端先按未完成待办、日记/普通备忘、已完成待办的分组顺序排序，再按创建时间降序、ID 降序分页，确保待办不会排到后续页。当天界面按相同顺序分组，不宣称当前页就是当天全部记录，存在后续页时显示「加载更多」。

搜索覆盖当前账号所有日期，在标题和正文中匹配。查询参数化，关键词中的 `%` 和 `_` 按文字搜索而非 SQL 通配符；首版先采用受限长度的文字匹配，数据规模需要时再扩展索引。关键词、类型变化或变更记录后重置分页。

一致性及错误处理：

- 所有读写均从会话取得 user_id；输入拒绝客户端传入所属账号；读取、更新和删除同时限定记录 ID 与当前 user_id。
- 无权访问和不存在的记录统一返回 404；401 按现有登录失效流程处理；422 为输入错误；409 为版本或创建请求冲突。
- 修改/删除使用版本条件执行原子操作；版本不匹配返回 409，不静默覆盖其他设备修改。
- 相同创建标识、相同内容重试返回既有记录；相同标识但不同内容返回 409。请求标识按当前账号唯一。
- 提交后发生超时、结果不确定时，保留提交快照及请求标识，允许重试同一内容；确认结果后再开始新的编辑，避免对相同标识提交不同内容。
- `completed=false` 或 `true` 表达明确目标状态，不使用会因重试反转两次的 toggle 接口。
- 月历只返回数量和状态，服务端错误与日志不回显日记正文。

## 5. 客户端交互和状态

页面顺序：原身体内容 → 生活日历标题/全部记录入口 → 月份导航 → 月历 → 所选日期 → 写日记/记备忘 → 当天列表。

- 月历默认选中今天，支持前后月、年月选择和回到今天；记录用小标记配合图例，不只依赖颜色。
- 点空日期也可以新建记录；未来日期禁用写日记，记备忘正常可用。
- 编辑页展示归属日期、可选标题、正文、备忘待办开关；列表的标题缺省时使用正文首行。
- 日历模块独立处理月份摘要和当天列表的加载、空白、错误状态。摘要失败不阻止已加载列表查看，当天列表失败可单独重试。
- 快速切换日期/月份、搜索时通过请求序号及 mounted 检查丢弃旧响应，避免旧数据覆盖新选择。
- 新增/编辑/完成/删除成功后刷新受影响日期和月份；改日期同时处理新旧月份。服务器变更成功而刷新失败时明确提示刷新失败，不能误报为保存失败并重复创建。
- 同一记录更新期间禁用重复操作；待办状态在服务器成功后更新，失败保留原状态。
- 编辑内容只保留在当前页面内存。提交中防重复点击；失败后内容仍可重试；未保存退出支持保存、放弃、继续编辑；持久草稿属于后续功能。
- 修改冲突保留当前输入，可加载服务器最新内容并由用户重新处理；不要自动覆盖。
- 删除前确认；未保存修改的处理覆盖系统返回和页面返回。退出登录或会话失效时清空编辑状态，并确保旧账号详情路由不会留给新账号。
- 维持现有奶油底色、绿色主色及卡片风格；检查小屏、键盘弹出、大字体和长中文正文。

## 7. 验证计划

后端使用现有 unittest + PostgreSQL 隔离测试模式，连接独立测试数据库，不连接正式数据验证。

- 迁移：从现有 head 升级，新表/索引/约束正确，旧表数据及序列保留；重复 upgrade 无副作用。空测试表回退可验证，正式库存在日记后删表会丢数据，正式回退优先回退应用并保留新增表。
- 接口：两账号分别创建记录；交叉读写删被拒；同日多条、空白内容、长度边界、未来日记、备忘待办约束正确。
- 一致性：相同创建请求重试只产生一条记录；不同内容重复标识拒绝；并发修改仅一个版本更新成功；旧版本删除拒绝。
- 查询：月份边界、闰年、年月切换、改日期后摘要变化、搜索中文/特殊字符、分页顺序和计数正确。

Flutter 验证：

- `flutter analyze`、`flutter test`，新增测试聚焦日期计算、编辑保护、请求竞态、账号隔离和状态同步。
- 页面测试覆盖身体数据失败时日历仍可显示、日历失败不影响身体操作、未来日记禁用、待办完成/撤销、修改后新旧日期刷新。
- 人工验收覆盖空账号、同日多条、跨年/闰日、长文与表情、网络失败/超时、搜索分页、系统返回、大字体、账号切换和重新登录。
- 后端执行 `python -m unittest discover -s server -p 'test_*.py' -v`；数据库用例被跳过时明确标为未验证，不以跳过视为通过。

## 9. 需要持续关注的实现点

- 身体页当前整页加载状态需做局部调整，避免日历随体重接口一起失败。
- `IndexedStack` 会保留页面状态，刷新与账号清理不能只依赖 initState；详情/编辑路由也要处理会话变化。
- 日记的「归属日」、创建时间和未来校验应统一口径，尤其是跨午夜和改变系统时区时。
- 保存成功与读取刷新成功是不同结果；网络超时的创建结果需能安全重试。
- 既有日历可参考交互和算法，但不要借此修改女性健康预测或训练计划逻辑。
