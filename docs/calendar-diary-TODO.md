# 生活日历后续功能 TODO

创建日期：2026-10-04。状态：全部待实现。

本清单记录首版之后的扩展；不代表已经进入本期开发。首版实施见[实现前规划](calendar-diary-implementation-plan.md)，产品规则见[需求草案](calendar-diary-requirements.md)。

P1 为优先扩展，P2 为后续按使用需求安排。每项只有完成相关验收后才能勾选；部分完成时仅勾选对应子任务，主项保持未完成。

## P1：当天生活概览

- [ ] 在所选日期下展示「当天生活概览」。
  - [ ] 读取已有体重、当天餐费、训练部位及打卡记录，不重复创建数据。
  - [ ] 支持点击摘要跳转到对应业务页并定位同一天。
  - [ ] 无数据显示「未记录」；实际记录的 0 元与未记录区分，不把缺失训练数据推断为休息日。
  - [ ] 修改相关业务记录后刷新摘要；某一来源失败时允许该来源单独重试。

依赖：首版日历及各业务按日查询；现有业务页需要支持接收目标日期。
验收：选历史日期显示该日而非今天的记录；跳转日期一致；摘要只读，不改体重、餐费或训练数据。

## P1：可选心情

- [ ] 为日记提供可选的简短心情记录。
  - [ ] 提供少量明确选项，允许不选、修改和清除。
  - [ ] 详情页和月历按用户选择展示心情标记。
  - [ ] 明确同一天多篇日记有不同心情时的展示规则，例如显示最新一篇已填写的心情。
  - [ ] 与女性健康的心情字段分别保存，不自动覆盖或推断。

依赖：日记字段与 API 的增量迁移。
验收：不选心情也能保存；修改/清除后显示同步；旧日记无需补填；不产生健康诊断。

## P1：标签与筛选

- [ ] 增加轻量标签，方便按主题回顾。
  - [ ] 支持为日记/备忘添加或移除标签，例如训练、学习、工作。
  - [ ] 支持标签筛选并与关键词、记录类型组合。
  - [ ] 统一标签去空白、重复名称、长度与数量限制；标签按账号隔离。

依赖：首版搜索和标签存储设计。
验收：筛选覆盖所有日期；不串账号；移除标签不删除正文或记录。

## P1：简短日记模板

- [ ] 增加「今日小结」「训练感受」「身体状态」等模板入口。
  - [ ] 空白新日记可插入预设提示，如「今天做了什么 / 感受如何 / 明天想做什么」。
  - [ ] 已有正文时只允许明确追加，不覆盖用户输入。
  - [ ] 模板只是编辑辅助，保存后仍为可自由修改的普通日记。

依赖：首版编辑页；预设模板可先使用客户端静态内容，无需模板管理后台。
验收：用户可跳过模板；再次插入不会静默覆盖；不自动读取身体或健康数据填入正文。

## P1：单次定时提醒

- [ ] 给待办增加可选的日期与时间提醒。
  - [ ] 明确提醒时区，区分计划归属日期和通知时间。
  - [ ] 实现 Android 通知权限请求、权限拒绝时的反馈及再次开启入口。
  - [ ] 创建、修改、完成、取消完成、删除时同步新增/调整/取消本机提醒。
  - [ ] 处理设备重启、App 更新、系统时间/时区变化及过期提醒。
  - [ ] 退出或切换账号清除旧账号提醒；登录后仅恢复当前账号有效提醒。
  - [ ] 通知默认只显示通用提示，正文展示由用户明确开启。
  - [ ] 明确跨设备策略：服务器保存提醒配置，本机通知由本机调度；处理卸载重装后的恢复。

依赖：首版待办闭环；Android 调度方案、通知权限及服务端提醒字段。选型时核对当时的系统和依赖文档。
验收：后台/重启后按选定调度策略可触发；关闭权限状态清晰；删除或完成后的旧提醒不再触发；不显示上一账号内容。

## P2：重复待办

- [ ] 支持每日和每周重复的事项。
  - [ ] 定义重复系列与每次发生记录；每次完成状态独立。
  - [ ] 编辑和删除区分「仅本次」与「本次及以后」。
  - [ ] 对跳过、改日期、结束重复和重复提醒明确行为。
  - [ ] 按需查询或生成发生记录，避免一次展开无限未来日期。

依赖：首版待办、重复规则和发生记录设计；若带通知，还依赖单次提醒功能。
验收：完成今天不完成明天；调整未来系列保留历史；重复记录不因重试或多设备使用被重复生成。

## P2：图片附件

- [ ] 为日记/备忘支持图片。
  - [ ] 支持选择、压缩、上传进度、失败重试、查看和移除。
  - [ ] 规定图片数量、大小和格式；服务端校验并按账号授权访问。
  - [ ] 正文失败、图片失败和整条记录删除时正确处理附件及未绑定上传。
  - [ ] 月历先保留记录标记，图片缩略图展示按需要单独设计。

依赖：附件存储、鉴权、上传 API 与资源清理方案；届时评估服务器磁盘或对象存储。
验收：上传失败不丢正文；其他账号不能访问图片；删记录后附件按约定清理；长图与大图不会撑破页面。

## P2：记录导出

- [ ] 支持按日期范围导出日记和备忘。
  - [ ] 先支持 UTF-8 文本/Markdown，包含日期、类型、正文和待办状态。
  - [ ] 支持筛选范围并通过用户主动操作保存/分享文件。
  - [ ] 增加数量较大时的进度和错误反馈，保持中文、换行及表情完整。
  - [ ] 根据需求再增加 PDF 和图片附件打包。

依赖：分页读取、Android 文件保存/分享能力。
验收：导出数量与所选范围一致；只包含当前账号；文件内容与实际记录一致；失败不误报成功。

## P2：日记访问锁

- [ ] 增加可选的日记访问锁。
  - [ ] 选择系统生物识别/设备凭据方案，设计启用、关闭及认证不可用时的行为。
  - [ ] 覆盖月历正文摘要、全部记录、搜索、详情、编辑和导出入口。

## P2：持久草稿

- [ ] 支持关闭页面或重启后恢复未提交内容。
  - [ ] 在现有「不向磁盘缓存业务数据」约束下，优先设计服务器草稿；如需离线本机草稿，先明确修改该产品约束。
  - [ ] 草稿按账号保存，区分新增草稿与既有记录的编辑草稿。
  - [ ] 定义保存时机、恢复提示、提交后清理、冲突和重复提交规则。
  - [ ] 草稿与正式记录分离，不计入月历正式记录数量和回顾统计。

依赖：草稿数据/API 和编辑生命周期；不能仅靠页面内存满足本项。
验收：重启重新登录后能恢复服务器已保存草稿；不串账号；恢复编辑草稿不会自动覆盖别人刚修改的正式记录。

## P2：周/月回顾

- [ ] 增加可核对的周/月生活回顾。
  - [ ] 展示写日记的天数、日记条数、待办完成数量，区分「天数」与「条数」。
  - [ ] 有心情功能后，展示用户填写的心情分布，未填写不参与计算。
